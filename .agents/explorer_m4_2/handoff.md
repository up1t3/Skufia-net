# Handoff Report: Swipe-to-Back Gestures (Milestone 4)

## 1. Observation
В ходе статического анализа и исследования исходного кода проекта Skufia-net были сделаны следующие наблюдения:
- **Устаревшая реализация свайпа:** В файле `frontend/chat.js` (строки 102–126) обнаружен примитивный обработчик жеста свайпа вправо, привязанный к глобальному объекту `document`:
  ```javascript
  document.addEventListener('touchstart', e => {
      touchStartX = e.changedTouches[0].screenX;
  }, false);
  document.addEventListener('touchend', e => {
      touchEndX = e.changedTouches[0].screenX;
      handleSwipe();
  }, false);
  ```
  Данный обработчик не имеет фазы `touchmove`, не перемещает интерфейс вслед за пальцем и конфликтует с вертикальным скроллом истории сообщений.
- **Интеграция с историей навигации:** В файле `frontend/messenger_app.js` (строки 1617–1633) определена функция `window.closeChatMobile(fromHistory)`, которая удаляет CSS-класс `chat-open` у элемента `.chat-layout` и выполняет команду `history.back()`. В строках 1886–1905 этого же файла находится слушатель события `popstate`, который синхронизирует состояние UI с кнопкой "Назад" браузера или устройства.
- **Макет интерфейса на мобильных:** В файле `frontend/style.css` (строки 2768, 3350) описано поведение для экранов `<= 768px`: панель `.chat-main` имеет `transform: translateX(100%)` по умолчанию и `transform: translateX(0)` при открытом чате (`.chat-layout.chat-open`). В PWA-режиме (`body.skufenger-fullscreen`) левая панель `.chat-sidebar` сдвигается на `translateX(-100%)`.
- **Аналог фильтрации скролла:** В файле `frontend/chat_core.js` (строки 769–822) реализован свайп влево для закрепления чатов в сайдбаре с корректной проверкой направления жеста:
  ```javascript
  if (!isSwiping && diffY > 5 && diffY > Math.abs(diffX)) { isScrolling = true; return; }
  ```

## 2. Logic Chain
1. Текущий свайп на `document` вызывает конфликты при любых горизонтальных движениях (выделение текста, прокрутка слайдеров, перемещение курсора в инпуте). Следовательно, область отслеживания тач-событий необходимо сузить до контейнера чата `.chat-main`.
2. Чтобы полностью избежать конфликтов с внутренними элементами чата (сообщениями, кнопками, полем ввода), необходимо ввести фильтрацию **Edge Swipe**: жест должен начинаться только у левой кромки экрана (`startX < 35px`).
3. При движении пальца по диагонали необходимо четко разделять намерение пользователя. Если вертикальное смещение преобладает над горизонтальным (`diffY > diffX`), то это вертикальный скролл сообщений, и обработка свайпа должна быть заблокирована до следующего касания. Если преобладает горизонтальное смещение вправо, активируется свайп назад (`isSwiping = true`), и стандартная прокрутка страницы прерывается через `e.preventDefault()`.
4. Для обеспечения плавной анимации в процессе свайпа необходимо отключать CSS transition у сдвигаемых элементов (`.chat-main` и `.chat-sidebar`) инлайновым стилем `transition = 'none'` и обновлять их свойство `transform: translateX()` синхронно с движением пальца.
5. При отпускании пальца (`touchend`) на основе пройденного расстояния (> 1/3 экрана) или скорости свайпа (> 0.3 px/ms) принимается решение: закрыть чат (плавный сдвиг до `100%` и вызов `window.closeChatMobile()`) либо вернуть его на место (сдвиг до `0`).
6. После окончания анимации перехода (через 250мс) все динамические инлайновые стили `transform` и `transition` должны удаляться, чтобы управление визуальным отображением вернулось стандартным CSS-классам.

## 3. Caveats
- Исследование проводилось в режиме **Read-only**. Никакие изменения в кодовую базу проекта Skufia-net не вносились.
- Тестирование жеста на физических мобильных устройствах или в эмуляторах не выполнялось.
- Значения порогов свайпа (`EDGE_THRESHOLD = 35px`, `VELOCITY_THRESHOLD = 0.3 px/ms`) являются стандартными для мобильных веб-приложений, но могут потребовать тонкой калибровки в процессе тестирования исполнителем.
- Исключение жеста Swipe-to-Back на интерактивных элементах выполнено с помощью поиска `.closest()` по базовым селекторам (`input, textarea, button`). При добавлении новых нестандартных элементов управления в чат их селекторы также нужно будет добавить в список исключений.

## 4. Conclusion
Архитектурный план и готовый код для реализации Milestone 4 спроектированы в полном объеме. Предлагается заменить устаревший обработчик свайпов в `frontend/chat.js` на новую логику Edge Swipe с поддержкой визуального сдвига панели и интеграцией с историей навигации. Все изменения локализованы внутри `frontend/chat.js` и не затрагивают другие файлы, минимизируя риск регрессии.

## 5. Verification Method
Для проверки корректности реализации исполнителю необходимо выполнить следующие шаги:
1. Применить патч к файлу `frontend/chat.js` с помощью команды:
   `git apply .agents/explorer_m4_2/proposed_swipe_to_back.patch`
2. Открыть приложение в мобильном режиме эмуляции Chrome DevTools (разрешение <= 768px).
3. Войти в любой чат (клик по элементу списка чатов).
4. Проверить отсутствие ложных срабатываний:
   - Скроллить историю сообщений вверх/вниз в центре экрана. Чат не должен закрываться или дергаться вбок.
   - Попытаться перетащить курсор в поле ввода сообщения (`#chat-input`). Чат не должен закрываться.
5. Проверить работу жеста Swipe-to-Back:
   - Провести пальцем вправо от левой границы экрана (менее 35px от края). Окно чата `.chat-main` должно плавно сдвигаться вслед за пальцем, а под ним должен выезжать сайдбар `.chat-sidebar`.
   - Отпустить палец, когда чат сдвинут более чем на треть экрана: чат должен плавно уехать вправо, закрыться, а PWA-версия должна вернуться к списку чатов. В консоли не должно быть навигационных ошибок.
   - Сдвинуть чат от края на небольшое расстояние и отпустить: чат должен плавно вернуться в исходное открытое состояние.
