# Отчет об исследовании фронтенда SKUFenger (Exploration Report)

## 1. Наблюдение (Observation)

В ходе детального исследования кодовой базы мессенджера SKUFenger (в режиме read-only) были изучены и задокументированы следующие компоненты фронтенда, стилей и тестового окружения:

### А. Архитектура и структура файлов фронтенда
Фронтенд представляет собой Single Page Application (SPA), написанное на чистом JavaScript (Vanilla JS) без использования тяжелых реактивных фреймворков. Основные файлы:
- **HTML**:
  - `frontend/index.html` (строки 1–1088): Основная разметка приложения. Содержит структуру входа/регистрации (Auth Overlay), оверлей установки PWA, модальные окна настроек, выбора тем, кадрирования аватара и управления папками чатов.
  - `frontend/messenger.html` (строки 1–779): Разметка страницы мессенджера, дублирующая формы авторизации и содержащая разметку для чат-интерфейса.
- **CSS**:
  - `frontend/style.css` (строки 1–4008): Глобальные стили приложения. Содержит объявления тем оформления (переменные), общие правила разметки, стили для личного кабинета, переключателя тем, кастомных скроллбаров и медиа-запросы для мобильной адаптации.
  - `frontend/chat.css`: Специализированные стили для трехпанельного интерфейса чата, аватаров, баблов сообщений и поля ввода сообщения.
  - `frontend/style-modal.css`: Стили для оверлеев и модальных окон.
- **JS**:
  - `frontend/messenger_app.js` (строки 1–1888): Скрипт инициализации приложения. Обрабатывает изменение видимой области вьюпорта (`visualViewport`), управляет состоянием экранов (view) и вкладок, переключением тем оформления и PWA-функционалом.
  - `frontend/chat_core.js` (строки 1–4313): Ядро чата. Реализует отправку и получение сообщений через WebSocket, отрисовку баблов сообщений, работу с контекстным меню сообщений, вложения (загрузку файлов), выпадающие списки (меншены) и автодополнение.

### Б. Темы оформления и CSS-переменные
В `frontend/style.css` (строки 1–103) определены 5 тем оформления, переключаемых дата-атрибутом `[data-theme]` на теге `body`:
1. **Cyber Glassmorphism** (дефолтная тема в `:root`):
   ```css
   --bg-dark: #0a0e14;
   --bg-panel: color-mix(in srgb, #111820 60%, transparent);
   --accent-cyan: #00f2ff;
   --text-main: #e0e6ed;
   --crt-display: block;
   --backdrop-blur: blur(12px) saturate(150%);
   --glow: 0 0 15px rgba(0, 242, 255, 0.4);
   ```
   Использует CRT-фильтр и сильное неоновое свечение.
2. **Telegram Dark** (`[data-theme="telegram"]`):
   Классическая приглушенная темная тема (шрифт `Inter`, без CRT-фильтра, синий акцент `--accent-cyan: #5288c1`).
3. **Neon** (`[data-theme="neon"]`):
   Фиолетово-неоновые тона (`--accent-cyan: #22d3ee`, `--accent-amber: #d946ef`, `--glow: 0 0 20px rgba(217, 70, 239, 0.4)`).
4. **Light OS** (`[data-theme="light-ios"]`):
   Светлая тема в стиле Apple (`--bg-dark: #F2F2F7`, `--text-main: #000000`, `--accent-cyan: #007AFF`).
5. **Cyber Gold** (`[data-theme="gold"]`):
   Премиальная черно-золотая тема с включенным CRT-эффектом (`--accent-cyan: #FFD700`, `--text-main: #FFF8DC`).

### Г. Контекстные меню сообщений, вложения и выпадающие списки
- **Контекстное меню сообщений** (`chat_core.js`, строки 1811–1888):
  Кастомное меню `.msg-context-menu` вызывается при обычном событии **`click`** на бабл сообщения:
  ```javascript
  bubble.addEventListener('click', (e) => {
      if (e.target.closest('a, video, audio, button, .msg-video-circle')) return;
      e.preventDefault();
      e.stopPropagation();
      // Отрисовка меню (Реакция, Переслать, Копировать, Ответить, Редактировать, Удалить)...
  ```
  Стандартный системный вызов контекстного меню браузера блокируется:
  ```javascript
  bubble.addEventListener('contextmenu', (e) => e.preventDefault());
  ```
- **Вложения (Media Upload)** (`chat_core.js`, строки 2142–2305):
  - При выборе файла в инпутах (`#chat-file-input`, `#chat-media-input`, `#chat-camera-input`) вызывается функция `uploadChatFiles(fileList)`.
  - Файлы сохраняются в массив `state.modalFiles` и отображаются в модальном окне предпросмотра `#media-preview-modal`.
  - Суммарный объем файлов проверяется на клиенте на превышение лимита в 50 МБ (строка 2147).
  - При отправке (`sendMediaPreview`) изображения сжимаются с помощью `window.compressImageHelper` (строка 2260).
  - Отправка файлов происходит по пути `POST /api/chat/upload_multiple` с добавлением `Authorization: Bearer` и `X-Idempotency-Key` (строки 2270–2272).
  - *Наблюдение*: В функции `uploadChatFiles` полностью отсутствует клиентская валидация расширений файлов. Любой опасный файл (например, `.exe` или `.bat`) передается на бэкенд, где валидация ложится на плечи сервера.
- **Выпадающие списки (Dropdowns)** (`chat_core.js`, строки 3075–3135):
  Меншены (упоминания пользователей `@`) обрабатываются в `handleChatInputMentions` при вводе символа `@` в `#chat-input`. Элемент `#mentions-dropdown` создается динамически и позиционируется абсолютно:
  ```javascript
  dropdown.style.cssText = `
      position: absolute;
      bottom: calc(100% + 10px);
      left: 20px;
      ...
  ```

### Д. Мобильная адаптивность, Safe Areas и visualViewport
- **Медиа-запросы** (`style.css`, строки 2747–2875):
  При ширине экрана <= 768px макет `.chat-layout` переходит в вертикальный режим. Боковая панель `.chat-sidebar` занимает 100% ширины, а `.chat-main` сдвигается за экран с помощью `transform: translateX(100%)`. При открытии чата добавляется класс `.chat-open` на `.chat-layout`, возвращающий `.chat-main` на экран (`transform: translateX(0)`).
- **CSS Safe Areas**:
  В `:root` инициализируется переменная `--safe-bottom: env(safe-area-inset-bottom, 0px)`. В `.chat-input-area` (стили поля ввода) отступ снизу задается как `padding-bottom: calc(8px + var(--safe-bottom));`, что предотвращает перекрытие интерфейса системными элементами на безрамочных устройствах (например, Home Bar в iOS).
- **visualViewport и Фокус ввода** (`messenger_app.js`, строки 1–36):
  Для предотвращения перекрытия инпута клавиатурой на мобильных устройствах, скрипт отслеживает изменение размеров вьюпорта через `window.visualViewport`:
  ```javascript
  function setAppHeight() {
      const vh = window.visualViewport ? window.visualViewport.height : window.innerHeight;
      const offset = window.visualViewport ? window.visualViewport.offsetTop : 0;
      document.documentElement.style.setProperty('--app-height', `${vh}px`);
      document.documentElement.style.setProperty('--app-offset', `${offset}px`);
      
      const historyEl = document.getElementById('chat-history');
      if (historyEl) {
          const isAtBottom = historyEl.scrollHeight - historyEl.scrollTop - historyEl.clientHeight < 50;
          ...
          requestAnimationFrame(() => {
              if (isAtBottom) { historyEl.scrollTop = historyEl.scrollHeight; }
          });
      }
  }
  ```
  Это гарантирует, что при фокусе `#chat-input` и появлении клавиатуры высота приложения (`--app-height`) уменьшается до размеров видимой зоны, а история сообщений автоматически скроллится вниз.

### Е. Анализ E2E-тестов (`tests/e2e/`)
В директории `tests/e2e/` находятся 4 тестовых файла и конфигурация Playwright:
1. **`playwright.config.ts`**:
   - Настраивает `baseURL` на `http://localhost:8008`.
   - Задает три проекта для эмуляции: "Desktop Chrome", "Mobile Safari (iPhone 14)" и "Mobile Chrome (Pixel 7)".
   - Устанавливает последовательный запуск (`fullyParallel: false`) с 1 воркером из-за общих тестовых учетных записей.
2. **`auth.spec.ts`**:
   - *Проблема*: На строке 5 жестко зашит переход на `await page.goto('https://skuf-net.ru');` вместо относительного пути `/` или использования `baseURL`.
3. **`chat-pipeline.spec.ts`**:
   - Проверяет полный сценарий: авторизация -> выбор чата -> отправка текста/файлов -> эмодзи -> запись голоса -> звонки -> профиль -> кнопка "Назад" на мобильных.
   - *Проблема*: На строке 12 объявлено `const BASE = process.env.TEST_URL || 'https://skuf-net.ru';`. Если тесты запускаются локально без переопределения переменной `TEST_URL`, они идут на внешний продакшн-домен.
4. **`mobile-rtc.spec.ts`**:
   - Тестирует стабильность WebRTC звонков в режиме эмуляции двух мобильных устройств.
   - *Проблема*: На строке 3 аналогично объявлено `const BASE = process.env.TEST_URL || 'https://skuf-net.ru';`.
5. **`chat-media.spec.ts`**:
   - *Проблема 1*: На строке 7 жестко забит порт 8007 (`await page.goto('http://localhost:8007');`). Этот порт используется для API документации бэкенда, и на нем не раздается фронтенд, что вызывает сбои.
   - *Проблема 2*: Используются устаревшие селекторы: `#username-input` (вместо `#login-username`), `#password-input` (вместо `#login-password`), `#login-btn` (вместо кнопки отправки формы `#login-form`). Из-за этого тесты стабильно падают.

## 2. Логическая цепочка (Logic Chain)

1. **Нестабильность и падение E2E-тестов**:
   - *Наблюдение*: Тесты в изолированном окружении валятся с ошибкой `net::ERR_CONNECTION_REFUSED` или таймаутами при обращении к внешнему хосту `https://skuf-net.ru` или неверному порту `8007`.
   - *Связь*: В `auth.spec.ts`, `chat-pipeline.spec.ts` и `mobile-rtc.spec.ts` захардкожен внешний домен `https://skuf-net.ru`. В `chat-media.spec.ts` прописан неверный порт `8007` и устаревшие селекторы.
   - *Вывод*: Для обеспечения работоспособности тестов необходимо переписать все вызовы `page.goto` на использование относительных путей `/` и `/messenger.html`, полагаясь на `baseURL` из конфигурации Playwright, а также обновить селекторы в `chat-media.spec.ts`.

2. **Проблема UX контекстного меню сообщений**:
   - *Наблюдение*: Событие `click` по баблу сообщения вызывает кастомное меню `.msg-context-menu` и вызывает `e.preventDefault()`, а событие `contextmenu` полностью предотвращается.
   - *Связь*: Обычный левый клик (или быстрый тап на мобильном) используется пользователями для выделения текста, копирования отдельных слов или перехода по ссылкам. Перехват клика полностью блокирует эти стандартные действия браузера.
   - *Вывод*: Необходимо изменить триггер вызова контекстного меню на десктопе на `contextmenu` (правый клик), а на мобильных устройствах реализовать событие долгого нажатия (`long-press`), сохранив стандартное поведение левого клика/быстрого тапа.

3. **Отсутствие клиентской валидации вложений**:
   - *Наблюдение*: Функция `uploadChatFiles` не проверяет расширения файлов перед отправкой формы в `POST /api/chat/upload_multiple`.
   - *Связь*: Тест `TC-04b` пытается загрузить опасный файл `malware.exe` и проверяет, что он отклонен. Из-за отсутствия проверки на фронтенде запрос в любом случае отправляется в сеть, нагружая бэкенд и расходуя мобильный трафик пользователя на заведомо вредоносные файлы.
   - *Вывод*: Требуется добавить строгую валидацию расширений файлов на стороне клиента (запретить исполняемые файлы `.exe`, `.bat`, `.sh` и т.д.) до отправки запроса в сеть.

## 3. Оговорки (Caveats)

- Исследование проводилось исключительно в режиме чтения (Read-only). Никакие изменения в кодовую базу не вносились.
- Анализ WebRTC звонков (`rtcManager.js`) и WebSocket-соединений производился на уровне интеграции с интерфейсом. Внутренняя логика сигнального сервера и протоколов обмена не входила в рамки задачи.
- Тестирование мобильной адаптивности и visualViewport проводилось на базе встроенной эмуляции мобильных устройств в Playwright и браузере (разрешения 390x844 для iPhone 14 и 412x915 для Pixel 7). Физические мобильные устройства не подключались.

## 4. Заключение (Conclusion) & Вехи разработки

Текущий фронтенд мессенджера SKUFenger имеет отличную основу с адаптивной версткой и кастомной логикой вьюпорта, однако страдает от проблем в тестовом покрытии, неконсистентности UX контекстных меню и пробелов в безопасности вложений.

Предлагается следующий детальный план разбиения разработки на **4 вехи (Milestones)**:

### Веха 1: Стабилизация тестового окружения и E2E (CI & Tests)
- **Задачи**:
  - Устранить жестко закодированные внешние ссылки (`https://skuf-net.ru`) во всех спеках. Перевести их на относительные пути.
  - Исправить `chat-media.spec.ts`: сменить порт с `8007` на `8008`, обновить селекторы полей ввода и кнопки входа на актуальные (`#login-username`, `#login-password`, `[type="submit"]`).
  - Убедиться в стабильности прохождения локального тестового набора.
- **Трудоемкость**: Низкая (1–2 дня).
- **Риски**: Таймауты при эмуляции видеокамеры в WebKit (Safari). *Снижение*: Добавить мокирование `getUserMedia` в тестах Safari или отключить медиа-тесты для Safari, оставив их для Chrome.

### Веха 2: Безопасность вложений и юридическое соответствие (Security & GDPR/FZ-152)
- **Задачи**:
  - Добавить клиентскую валидацию расширений файлов в `uploadChatFiles` (запрет отправки исполняемых файлов `.exe`, `.bat`, `.sh`, `.msi`).
  - Добавить индикатор прогресса (Progress Bar) загрузки файлов при отправке крупных вложений в `#media-preview-modal`.
  - В блоке ФЗ-152 на формах регистрации сделать текст «Федеральным законом № 152-ФЗ» кликабельным. Ссылка должна открывать модальное окно с текстом политики конфиденциальности Skufia-Net.
- **Трудоемкость**: Средняя (3–4 дня).
- **Риски**: Попытки обойти клиентскую валидацию. *Снижение*: Дублировать проверки на стороне бэкенда (уже частично реализовано).

### Веха 3: Рефакторинг контекстных меню и выпадающих списков (UX Refactoring)
- **Задачи**:
  - Перенести вызов меню сообщений с события `click` на событие `contextmenu` (правый клик для десктопа) и реализовать событие `long-press` (долгое нажатие для мобильных).
  - Восстановить стандартное поведение выделения текста при клике левой кнопкой мыши.
  - Добавить в контекстное меню сообщения функции: цитирование (Reply), копирование ссылки на сообщение, закрепление (Pin).
  - Реализовать автоматический расчет положения выпадающих списков (`#mentions-dropdown`), чтобы они не выходили за рамки экрана.
- **Трудоемкость**: Средняя (4–5 дней).
- **Риски**: Конфликты `long-press` со стандартным поведением выделения текста в iOS Safari. *Снижение*: Использовать CSS-правило `user-select: none` только на время удержания тапа.

### Веха 4: Калибровка мобильного UX и жестов (Mobile Precision)
- **Задачи**:
  - Интегрировать Safe Areas (`safe-area-inset-top`, `safe-area-inset-left`) для боковой панели и модальных окон на устройствах с вырезами (Notch, Dynamic Island).
  - Реализовать поддержку свайп-жестов (`swipe-to-close`) для закрытия чата и возврата к списку контактов на мобильных устройствах.
  - Устранить микро-скачки высоты интерфейса при скрытии/показе клавиатуры в мобильном Safari.
- **Трудоемкость**: Средняя (4–5 дней).
- **Риски**: Отличия в поведении visualViewport API в старых версиях мобильных браузеров. *Снижение*: Использовать троттлинг событий `resize` и фоллбеки на `window.innerHeight`.

## 5. Метод проверки (Verification Method)

Для независимой проверки результатов исследования выполните следующие шаги:

1. **Проверка верстки согласия ФЗ-152**:
   - Откройте `frontend/index.html` (строки 102–111) или `frontend/messenger.html` (строки 90–99).
   - Убедитесь в наличии чекбокса `#reg-pd-consent` с атрибутом `onchange`, блокирующим или разблокирующим кнопку `#reg-submit-btn`.
2. **Проверка visualViewport**:
   - Откройте `frontend/messenger_app.js` (строки 1–36).
   - Проверьте наличие функции `setAppHeight()` и подписок на `visualViewport.addEventListener('resize', setAppHeight)`.
3. **Запуск E2E-тестов**:
   - Запустите локальный бэкенд на порту 8008.
   - Запустите команду тестирования в терминале (через Git Bash / PowerShell):
     ```bash
     TEST_URL=http://localhost:8008 npx playwright test tests/e2e/chat-pipeline.spec.ts --project="Desktop Chrome"
     ```
   - Заметьте ошибки соединения (ERR_CONNECTION_REFUSED), если локальный бэкенд не запущен, что подтверждает хардкод адресов в тестах при их запуске без явного указания `TEST_URL`.
