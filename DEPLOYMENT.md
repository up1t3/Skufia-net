# Skufia-Net Deployment Guide

## Идеальный процесс деплоя (Zero-Error Pipeline)

Этот проект использует единый локальный Node.js скрипт для деплоя, чтобы исключить человеческий фактор, избежать зависаний SSH и гарантированно сбросить кэш у клиентов.

**НИКОГДА НЕ ИСПОЛЬЗУЙТЕ bash скрипты вроде `deploy.sh` или `run_deploy.sh` для деплоя в этом проекте!**

### Как деплоить:
Всегда запускайте одну команду из корня проекта:
```bash
node deploy.js
```

### Что делает `deploy.js`:
1. **Auto-commit**: Автоматически коммитит все незафиксированные изменения локально.
2. **Versioning & Cache Busting**: Генерирует новую версию (напр. `v2.2.0_01.05_13:20`), обновляет `index.html`, `messenger.html` и, самое главное, `CACHE_NAME` в `frontend/chat-sw.js`.
3. **Git Sync**: Создает коммит релиза и делает `git push origin main`.
4. **Remote Execution**: По SSH подключается к серверу (через переменные из `.env`), делает `git reset --hard && git pull`, полностью пересобирает фронтенд и бэкенд в Docker (без кэша), и переподнимает инфраструктуру через `docker compose`.

### Требования к окружению
В корне проекта должен лежать файл `.env` со следующими переменными для SSH-клиента:
- `SERVER_IP`
- `SERVER_USER` (по умолчанию root)
- `SERVER_PASSWORD`

### Памятка для ИИ (LLM Instructions)
Если пользователь просит "задеплоить", "выкатить на прод" или "сделать билд":
1. Убедитесь, что все изменения готовы.
2. Просто запустите команду `node deploy.js` через инструмент `run_command`.
3. Скрипт сам обо всем позаботится. Не нужно вручную менять версии или писать bash-скрипты.
